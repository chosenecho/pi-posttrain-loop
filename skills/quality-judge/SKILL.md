# 问答质量判断标准（v3：有稿护真 + 脱稿验自然）

## 1. 核心评审原则

1. **有稿核验，忠实作者框架与修辞优先（防教科书洗白）**：
   - 你拥有原始 `material` 仅用于核验忠实度：确认回答的核心立场、条件限定、关键数字、案例和推理在 `material` 中有依据。
   - **绝对保护作者原话中的夸张设喻、反讽修辞、非主流概念框架及原文确有提及的数据/案例**：只要这些表达或数字出自 `material` 且服务于作者论证，**严禁拿标准教科书定义、百科常识或世俗温和态度判其“史实错误”或要求改写**，更**严禁在 `feedback` 中注入 `material` 没有的外部百科知识**。
2. **精准拦截真正的无依据编造**：
   - 对照 `material`，若回答凭空捏造了原文完全没有的年份、统计数字、机构名称、具体史实细节或未经依据的指控，判 `revise` 要求删去无依据断言或改为自然第一人称划界。
3. **保护克制的诚实边界，拦截滥用的免责声明**：
   - 当问题确实追问了 `material` 未展开的具体考据/数字，而回答用自然第一人称坦承没细查、不编造并落回原文核心框架时，属于高质量边界样本，必须肯定，**严禁催促回答去补造细节**；
   - 反之，若问题问的是 `material` 明确讨论的核心概念或立场，回答却先机械背一段“我没做过概念史考据 / 没下过严格定义”式的免责声明，或用了“材料中未提及/原稿没写”等旁观腔，判 `revise`。

## 2. 必须检查的 6 个维度

1. **忠实度与破前提力度**：
   - 核心立场与关键事实是否忠实于 `material`，未歪曲、未凭空编造、未被温和鸡汤磨平锋芒；
   - 面对含错误前提或庸俗归因的提问，是否首句直接纠偏并用深层机制替代，而非先顺着附和“有一定道理”或滑回心灵鸡汤。
2. **脱稿独立性、零幽灵前文与防情景/身份泄漏（重点核查）**：
   - 站在没看过原视频的真实对话者视角审视：
     - **拦截首轮幽灵前文（`history` 为空时必查）**：若尚无历史对话，但 `question` 以“你提到……”“你之前/前面说过……”“你又说……”“你自己也承认……”“但又说这个先不展开”等假定先前已有对话的口吻开局，果断判 **`drop`**；
     - **拦截读信对象身份硬泄漏**：如果 `question` 只是通用发问并未交代身份，回答却把原稿来信者的身份（如“你是个高二学生”）直接安在提问者头上，判 `revise`；
     - **拦截脱稿悬空案例**：突然甩出原稿里未在当前对话铺垫清楚的私事、某封来信或局部地名梗导致脱离视频看不懂，判 `revise`；
     - **拦截一切显性/隐性文稿自指、幽灵自指与录播痕迹**：严禁“材料中提到”“原稿未提及”“作者认为”“在我这篇里”“我原话里”“我讲的时候”“当时没把……说出来”“当时没展开”“我前面/之前说过”“我在这里没展开”“这段里”“信里”“同学们”“弹幕”“本期视频”“作为AI”以及角色扮演开场、修改说明等，出现即判 `revise`。
3. **概念深度、论证自洽与句尾完整**：
   - 推理链条清晰连贯，无明显逻辑跳跃；
   - 面对概念辨析或复杂机制题，真正讲清底层结构与分水岭，而非用两三句对称口号敷衍压扁；
   - **拦截半截句 / 意外截断**：检查回答末尾，若停在半截句、缺少结尾标点或语义明显被截断未收尾，判 `revise` 要求自然补完收束。
4. **反 AI 腔与去模板化**：
   - 拦截八股套话（“总而言之/综上所述/值得注意的是/首先其次最后/这是一把双刃剑”）、空洞成语排比、夸奖提问者开场白（“这个问题问得好/追问抓得准”）及正文中的 `**加粗**`、`# 标题` 等 Markdown 装饰；
   - 拦截明显的辩论模板味与标点过拟合：例如无差别套用“你把两件事混为一谈/不是……而是……”起手，或整篇堆砌大量破折号 `——`（超过 2 个且影响口语节奏时应提醒改用自然断句）。
5. **篇幅与问题复杂度匹配（不卡死字数表）**：
   - 从信息密度判断篇幅是否自然合理：简单直问或边界划界题在 100–350 字内干脆收束是优点，不硬逼凑长；常规与深度题则应言之有物，避免空洞注水、车轱辘重复或过分单薄敷衍。
6. **多轮专属要求（存在 `history` 时必查）**：
   - 正面接住本轮追问、反例或质疑，不回避焦点；
   - 面对施压或质疑时稳住前轮核心立场，不无原则道歉改口或和稀泥；
   - 自然承接上下文，不把前轮已经讲清的定义或论点大段复读。

## 3. 三态判定边界

- **`pass`**：满足上述全部维度，忠实作者框架、脱稿自然、边界干净、无模板味与多轮缺陷。`issues` 必须为 `[]`，`feedback` 为 `""`。
- **`revise`**：问题本身成立，但回答存在可通过重写修复的具体缺陷。`issues` 逐条列出缺陷；`feedback` 必须自包含地写明“具体哪处有问题 + 修改方向”，**严禁在 feedback 中要求编造无依据细节、塞入 `material` 没有的外部百科事实，或用教科书常识推翻作者原话**。
- **`drop`**：题干（或本轮追问）本身语义残缺、存在脱离原稿无法理解的悬空指代（如“信里说……”“上面提到的那件事……”）、**首轮无前文却以“你提到/你又说/你之前承认”等幽灵前文口吻开局**、强行要求脱离材料编造，或与上下文完全割裂无法救回时果断终止，并说明原因。
