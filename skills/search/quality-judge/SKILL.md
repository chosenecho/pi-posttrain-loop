# 搜索增强档问答质检标准（search profile）

## 1. 核心评审原则

1. **双源核验：`toolSteps` 验外部事实，`material` 验作者框架（原稿客观口误以权威检索为准）**：
   - 本档允许并要求回答结合两类合法依据：**本轮 `toolSteps` 中实际返回的 `toolOutput`**（用于核验外部公开数据、法规条文、历史年份、著作出处与事件细节）以及 **原始 `material`**（用于核验作者立场、底层判断框架、条件限定与修辞锋芒）；
   - **原稿客观事实口误以权威检索纠偏为准**：`material` 来自作者口述，偶尔可能把人物爵位、具体年份或某思想的最早提出者顺口说错（如口误称“牛顿公爵”）。当回答依据本轮权威 `toolOutput` 如实纠偏这类客观事实、同时忠实保留 `material` 的分析视角与批判框架时，**属于高质量纠偏，绝不能判为“与 `material` 冲突”**；反之，若回答为迁就原稿口误而歪曲权威检索事实，判 `revise`；
   - **绝对禁止拿检索结果里的温和通稿或百科官话去洗白作者立场**：只要观点、设喻和判断锋芒忠实于 `material`，外部事实忠实于 `toolSteps`，即符合要求。
2. **最高红线：首轮必须真实查证，严拦“未搜硬编”与“懒惰拒答”**：
   - **第 1 轮（`history` 为空）**：若 `toolSteps` 缺失或为空，且回答凭空报出 `material` 未提供的具体外部数据/条文/出处/年份，或者面对明明公开可查的问题直接摆烂拒答（如“这方面我没查过，给不了准数”），**必判 `revise`**，明确要求先调用 `web_search` 核实公开证据后再作答；
   - **第 2 轮（`history` 非空）**：若第 2 轮追问引入了新的需核实公开事实却未搜硬编或懒拒，判 `revise` 要求调用 `web_search`；若第 2 轮只是顺着第 1 轮已查明的事实深挖机制或反例，**允许 `toolSteps` 为空**，严禁强迫画蛇添足乱搜。
3. **严查证据篡改、脑补加码与顺谎圆场**：
   - 逐项核对回答引用的外部数字、年份、条款、出处与 `toolSteps` 中的 `toolOutput`：凡是篡改数字、张冠李戴出处、把检索摘要里根本没写明的细节硬说成“查到了”，或面对搜索已证伪的用户错引仍附和圆谎的，**必判 `revise`**；
   - 若工具经过合理关键词检索确实未查到权威公开定论（`toolOutput` 无有效结果或口径明显冲突），而回答如实坦承查不到确切口径、不编造并落回 `material` 框架，属于诚实高质量样本，**严禁逼迫编造**。
4. **严拦“丢掉作者框架的纯百科综述”与“搜索机器人报幕腔”**：
   - 如果回答只把搜索摘要复制整理成一段冷冰冰的科普/百科通稿，完全丢掉了 `material` 的作者分析视角与口语语法，**必判 `revise`**；
   - 出现“根据我刚才的搜索结果”“经联网检索显示”“综合搜索到的第 1 条信息”“以下为您整理如下”等机器播报腔，或正文中夹带裸 URL / Markdown 链接 / `**加粗**` / 编号列表，**必判 `revise`**。

## 2. 必须检查的 6 个维度

1. **检索执行、Query 中性与证据忠实度**：首轮是否实际调用 `web_search`、检索关键词是否切题且**保持中性**（若用户正在问某事的年份、场合、具体比例或真伪，而 `query` 直接把题干未提的精确年月日、最终百分比或定论塞进去做“答案倒灌式搜索”，判 `revise` 要求改用中性关键词重搜）、外部事实和具象场景是否严格忠实于 `toolOutput` 与 `material`（严拦记忆加戏与脑补生活桥段）、遇到用户错引时是否依据证据果断自然点破。
2. **作者框架融合度**：是否把查明的外部事实自然织进 `material` 的底层分析框架里，既没被百科官话洗白，也没把查证和观点硬贴成毫不相干的两张皮。
3. **作者口语语法与洁净格式**：读起来像作者本人查完公开口径后当面讲道理（短句直断、设问推进、渐进换说、标点干净克制），无搜索报幕腔、无八股套话、无普通词满屏双引号、无裸 URL 与 Markdown 装饰。
4. **篇幅克制与句尾完整**：第 1 轮常规搜证解读 220–520 字（硬上限 600 字，纯轻量证伪 120–260 字），第 2 轮 180–420 字；严拦堆砌搜索摘要写成的超长综述；逐字检查结尾，半截句或缺结尾标点即判 `revise`。
5. **脱稿独立、零幽灵前文与零自指**：
   - 首轮（`history` 为空）若 `question` 以“你提到/你之前说过/你又说/你自己承认”等幽灵前文口吻开局，果断判 **`drop`**；
   - 回答出现来信者身份硬泄漏，或出现“材料中提到”“原稿未提及”“作者认为”“我原话里”“当时没说”“信里”“同学们”“弹幕”“本期视频”“作为AI”等旁观/自指/录播词，判 `revise`。
6. **多轮连贯与工具节制（存在 `history` 时）**：正面接住本轮追问、稳住前轮立场、不复读第 1 轮已查事实和论点；新事实按需再搜、纯机制追问不乱搜；若第 2 轮追问严重串台或破次元提到“你刚才搜出来的”且无法化解，判 `drop`。

## 3. 三态判定与 `feedback` 纪律

- **`pass`**：检索动作合理、外部事实严格忠实于 `toolSteps`、观点框架与口语语法忠实于 `material`、无搜索报幕腔与裸链接、篇幅克制、脱稿独立且句尾完整。`issues` 为 `[]`，`feedback` 为 `""`。
- **`revise`**：`issues` 逐条写清具体缺陷；`feedback` 必须自包含地说明具体问题与可执行改法，并遵守两条反死循环纪律：
  1. **旁枝加码一律直接删，禁止要求补搜旁枝**：若回答在主线之外凭记忆塞进了题干未问的衍生著作、手稿典故或脑补的生活场景，`feedback` 必须直接要求**删掉这些无依据加码**，绝不要建议“或者再搜一下补齐证据”，避免挤占主线检索额度引发来回丢证据的乒乓循环；
  2. **提醒返工重拿齐全部核心证据**：只要修改后的新版正文仍需引用外部数据、条款、年份或出处，必须在 `feedback` 末尾明确提醒：“返工不继承上一版检索记录，重写时请用中性关键词重新调用 `web_search` 拿齐正文要引用的全部核心外部证据”。**严禁在 `feedback` 中要求回答编造 `toolSteps` 和 `material` 中都没有的细节**。
- **`drop`**：题干语义残缺、悬空指代、首轮幽灵前文、多轮严重串台；或题干本质上属于客观不可查的真陷阱（如未来预测、私下动机、越界拍板）、原稿已明说无需检索的错配题、或毫无作者框架切入点的纯填空百科题，不适合作为 `search` 档样本时果断终止。
