# 长流程规划档问答质检标准（todo profile）

## 1. 核心评审原则

1. **最高红线：首轮必须有真实、实质、闭环的 `todo` 工具调用轨迹**：
   - **第 1 轮（`history` 为空）**：检查 `toolSteps` 中对 `todo` 工具的调用：
     - **漏调工具**：若完全没有调用 `todo` 工具就直接输出正文，**必判 `revise`**，要求先调用 `todo(add)` 拆解 3–5 个分析子阶段并逐项 `todo(toggle)` 完成后再输出正文；
     - **只建不勾（未闭环）**：若只调用了 `todo({ action: "add" })` 却没有对应的 `todo({ action: "toggle", id })` 将各子任务标记为 Completed，**必判 `revise`**；
     - **形式主义废话 Todo**：若 `add` 的 `text` 是“1. 理解问题 2. 阅读材料 3. 思考逻辑 4. 总结回答”这类与当前问题实质分析毫无关系的通用过场套话，**必判 `revise`**，要求结合 `material`（及 `taskSpec.expected_phases` 参考）拆出具体、有信息量的分析子目标（3–5 项为宜）。
   - **第 2 轮（`history` 非空）**：第 2 轮追问不强制要求调用 `todo`，按需自然作答或检索即可。
2. **正文与 Todo 清单必须深度咬合，且绝对零破次元报幕**：
   - 对照 `toolSteps` 中添加的每一条 Todo 子目标，检查 `answer` 正文是否真正把每一项都展开讲透了；若清单列了 4 项、正文却漏掉其中 1–2 项虎头蛇尾，**判 `revise`**；
   - **严拦破次元报幕腔**：若 `answer` 正文中出现“我列了 Todo 清单”“按照待办第 1 项/第 2 步”“完成上述清单后”“根据我刚才搜索的结果”等后台工具泄漏词，或直接用 `1. 2. 3.` 编号列表/`**加粗**`标题把 Todo 贴进正文，**必判 `revise`**。
3. **忠实于 `material` 与可选的 `web_search` 证据**：
   - 核心立场、底层框架、条件限定与修辞锋芒必须忠实于 `material`；
   - 若 `toolSteps` 中同时调用了 `web_search`，正文引用的外部数据、条文、年份或出处必须严格忠实于 `web_search` 的 `toolOutput`，严禁未搜硬编或篡改数字。

## 2. 必须检查的 6 个维度

1. **`todo` 轨迹质量与闭环度**：首轮是否建立了 3–5 个贴合题干与 `material` 逻辑的实质子目标，且全部通过 `toggle` 勾选完成。
2. **正文兑现度与结构纵深**：正文（首轮目标 650–1,400 字，3–5 个自然段；次轮 300–650 字）是否按清单顺序层层推进、无漏项、无逻辑断层。
3. **忠实度与事实依据**：观点框架是否忠于 `material`，外部公开事实（若有）是否忠于 `web_search` 结果，无脑补加戏。
4. **作者口语语法与洁净格式**：是否以短句直断、设问推进、渐进换说自然串联各阶段，纯文本自然段，无 Markdown 标题/加粗/列表/链接，破折号克制，句尾完整带标点。
5. **脱稿独立、零工具报幕与零自指**：
   - 首轮若 `question` 含幽灵前文（“你提到/你之前说”）或悬空指代（“视频里/信里”），直接判 **`drop`**；
   - 回答出现工具报幕腔、文稿自指词（“材料中提到/作者认为/我原话里”）、录播词（“同学们/大家/本期视频”）或来信者身份泄漏，判 `revise`。
6. **多轮连贯（存在 `history` 时）**：正面接住本轮追问、不复读前轮长文、立场前后一致。

## 3. 三态判定与 `feedback` 纪律

- **`pass`**：首轮 `todo` 拆解实质且完整勾选闭环、正文逐项兑现且零破次元报幕、忠实于 `material`（及检索证据）、口语语法地道、篇幅达标且句尾完整。`issues` 为 `[]`，`feedback` 为 `""`。
- **`revise`**：`issues` 逐条列明缺陷；`feedback` 给出明确可执行的修改指令，并在末尾提醒：“返工不继承上一版工具调用记录，重写时请重新调用 `todo` 完成实质子目标的 `add` 与 `toggle` 闭环（若引用外部公开事实请同步调用 `web_search`），并输出纯文本完整正文”。
- **`drop`**：题干本身语义残缺、含幽灵前文或悬空指代；或题干过于简单单薄、根本不存在多阶段拆解空间，强行套 `todo` 只会沦为凑数注水时，果断判 `drop`。
