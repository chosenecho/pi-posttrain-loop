# 0001. 使用统一 SQLite 作为唯一真相源，JSONL 仅作按需导出投影

我们将所有语料版本、视频分区、问题、运行批次、角色技能 SHA-256 快照、多轮对话轮次、每次返工尝试、每次底层模型调用以及最终通过结果统一存储在内置 `node:sqlite` 数据库中，而把训练用 `.jsonl` 降级为按需导出的只读投影。

若直接将流水线产出写入零散 JSONL 文件，一旦需要核查“某条样本是由哪一版 Skill 产出的”“哪些 `revise → pass` 返工对可以回收做 DPO”“某次中断后哪些题目需要增量重跑”或“如何从物理上阻止 `test`/`dpo` 分区视频混入训练集导出”，就必须编写脆弱的跨文件解析脚本且无法用数据库约束与触发器强制守卫。

## Consequences

- 数据库层通过触发器与事务直接强制核心领域不变量（如：多轮样本必须所有对话轮通过才能写入 `results`、已入库 `results` 引用的过程记录不可原地篡改、`video_splits` 一旦登记终身不可变、只有 `ready` 状态的 Skill 且属于 `train` 分区的正式运行才允许导出训练 JSONL）。
- 要求运行环境 Node.js `>= 22.19.0`（提供原生 `node:sqlite`），免除了 C++ 原生插件编译依赖。
