# 0002. 每个角色调用均启动独立无状态 Pi Agent 并实行角色级 Skill 白名单隔离

每次 Pi 角色调用（出题、作答、质检、追问、思考补写及独立评测角色）均创建全新 Agent，仅通过显式构造的最小 JSON 消息传递当前步骤所需的上下文，每个角色只加载其专属 `SKILL.md`。这里的隔离单位是一次 runner 调用，不是一次 HTTP 请求：同一次工具作答可在该 Agent 内多步调用工具并读取回执；角色切换、返工或调用重试会重新创建 Agent。候选模型盲测走独立 HTTP 客户端，继续保持其脱稿输入边界。

如果在同一个多轮 Agent 会话里交替扮演“作答者”与“质检员”，或者让作答角色看到质检评分细则、让评测出题角色看到训练出题模板，模型会迅速产生自我迎合偏差（Self-bias）与评价标准串味，且第 2 次返工重答时携带的历史废案会严重污染上下文并推高 Token 成本。

## Consequences

- 第 $N$ 次返工重答时，`answer` 角色只接收原始材料、当前问题、上一版回答与上一轮质检反馈（携带前序已通过轮次的干净对话历史），绝不携带更早的失败草稿或内部质检判定标签。
- 每次运行开始时将实际注入的系统提示词与各角色 Skill 正文及 SHA-256 快照写入数据库，以便恢复当时的角色边界；模型服务的随机输出不因此变成确定性结果。主合成由 [plan.ts](../../src/synth/plan.ts) 在打开写库前解析不可变配置，九种 profile 的 Skill、轮数、题数和工具默认值统一来自 [profiles.ts](../../src/synth/profiles.ts)。
- [共享 Pi runner](../../src/shared/pi-runner.ts) 保持通用，只负责模型、Agent、搜索及外部注入工具的生命周期和审计回调；共享层不依赖 synth。[synth/tool-runner.ts](../../src/synth/tool-runner.ts) 负责 profile 专用工具、任务元数据投影与用户模拟器隔离。它在序列化前去掉 `_questionMode` / `_taskSpec`，只将允许字段发送给 Answer；隐藏用户设定与缺失槽位供模拟器使用，评审按自身最小输入查看任务依据。
- `todo` 的调用预算及 `question` / `questionnaire` 共用的澄清预算在异步执行前占用，失败或执行后取消不退还；各工具共享该 runner 调用的取消信号与截止时间。取消先中止 Agent 和工具，再等待 `agent.waitForIdle()` 与真实工具 promise，之后才返回控制权；工具审计可在 drain 中补写终态，外层据此结束运行并释放数据库 owner。
- 工具失败、限额与取消属于审计事实；成功 `ToolStep` 才是训练投影候选。两种记录保持分开，避免把运行诊断当作模型应学习的工具使用。完整边界与收尾顺序见 [架构概览](../architecture.md) 和 [SQLite 统一存储设计](../sqlite-design.md)。
